## 1. bkInfoM 整体结构

bkInfoM 是炫彩界面库 (XCGUI) 的样式宏语言，出现在几乎所有元素的 `bkInfoM="..."` 属性上。库本身没有公开文档，以下语法是从 humbox 项目全部 57 个布局文件中反推归纳的。

**整体结构**：被 `{}` 包裹、以 `;` 分隔的**分段序列**，每段 `编号:参数(值列表)` 或 `编号(...)`：

```text
{sizeT:W,H; 99:1.9.9; 98:状态映射; <绘制段0>; <绘制段1>; <绘制段2>; ...}
```

- 段间用 `;` 分隔，最后一个段后通常也带 `;` 再闭合 `}`
- **绘制段按出现顺序从 0 开始编号**（段0、段1、段2…），`98:` 状态映射里的数字就是这些段的索引
- 配套属性 `bkInfoM_nameT="0(矩形)1(文字)2(图片)"` 给每段一个设计器里的人类可读标签——修改时对照它定位段落

| 头部段 | 作用 | 示例 |
|---|---|---|
| `sizeT:W,H` | 设计参考尺寸（可选，仅设计器使用） | `sizeT:120,20` |
| `99:1.9.9` | bkInfoM 格式版本号，**必须写** | 所有文件恒为 `99:1.9.9` |
| `98:...` | 状态→绘制段映射，决定交互时用哪套段 | 见下 |

## 2. 状态映射 `98:` 与状态码表

每项格式 `状态码(段索引列表)`。同一码出现多次时后项覆盖/叠加前项（如 `98:16(0,1)32(2,1)64(3,1)2(4,5)`：正常态画段0+1，悬停改画段2+1，按下改画段3+1，**禁用态画段4+5**）。已从项目实例确认的状态码：

| 状态码 | 含义 | 典型用法 |
|---|---|---|
| `16` | leave/normal——离开（默认）态 | `16(0)` 普通按钮；`16(0,1)` 窗口背景=段0、边框=段1 |
| `32` | stay/hover——鼠标悬停 | `32(0,3)` 悬停时叠加段3 |
| `64` | down/press——按下 | `64(1,4)` |
| **`2`** | **disable——禁用（控件 `启用(假)` 时）** | `2(4,5)`；会 `.启用(假)` 的按钮**必须**写这一层 |
| `128` | check+leave（已勾选且未悬停）= `0x80`+0 | `128(0,1,3,4)` |
| `144` | check+stay（已勾选且悬停）= `0x80`+16 | `144(2,6)` |
| `160` | check+down（已勾选且按下）= `0x80`+32 | `160(3,6)` |
| `192` | check 另一变体（已勾选）= `0x80`+64 | `192(2,6)` |
| `272` | radio/check 未选中 · leave = `0x100`+16 | `272(0,4)` |
| `288` | radio/check 未选中 · stay = `0x100`+32 | `288(1,4)` |
| `320` | radio/check 未选中 · down = `0x100`+64 | `320(1,4)` |
| `258` / `130` | 未选中 + 禁用 = `0x100`+2 / 已勾选 + 禁用 = `0x80`+2（组合态，非纯选中态） | 见 §2.2 注记 |
| `24` | comboBox 编辑框态 | `24(0,1)` |
| `20` | comboBox 弹起态 | `20(0,1)` |
| `40` | comboBox 按钮态 | `40(0,1)` |
| `36` | comboBox 下拉态 | `36(0,1)` |
| `72` | comboBox-2（悬停） | `72(0,2)` |
| `68` | comboBox-2（按下） | `68(0,2)` |
| `1` | 窗口绘制序（login.xml 顶层窗口用到 `98:1(0,2,3,1)`） | 特例 |
| `8` | 单选禁用/半透明变体（skin.xml 单选） | `272(8,1,0)` |

各码可组合叠加：`98:16(0)32(2)64(3)2(1)` 表示四个态各画不同段。**每态的段列表是从 0 计数的绘制段索引**，且通常包含一个「底图/底色段」（索引 0 或 1）再加修饰段。

### 2.1 状态码算术（本文件采用的判据）

状态码是位标志之和：`16`=leave 基准、`32`=stay 基准、`64`=down 基准、`0x80`=已勾选标志、`0x100`=勾选/单选控件标志。因此：

| 状态码 | 分解 | 语义 |
|---|---|---|
| `258` | `0x100` + 2 | 未选中 + 禁用 |
| `130` | `0x80` + 2 | 已勾选 + 禁用 |

上表「已勾选 / 未选中」各族的 `0x80` / `0x100` 分解见 §2 状态码表第 4 列。

**结论：`2` = 禁用（disable），不是选中态。**
> 源冲突注记：`bkinfom-grammar.md` 的状态表把 `2` 标为「check/select——选中态」，但同一文件的实例（其 §2 的 `98:16(0,1)32(2,1)64(3,1)2(4,5)`）把 16/32/64 解释为「正常/悬停/按下」三个态，剩下的 `2` 只能是**禁用**，其行文亦写「禁用态画段4+5」——即该表自己给出的读法与它那一行标签矛盾。`界面md 00 §22` 明写「`2` disable」，`07 §3.1` 专列「状态映射必须含禁用」。grammar 那一行属源误读，本文件按 **2=禁用** 写。

### 2.2 radio / check 已选态码

**正文口径（采用）**：未选中 = `272` / `288` / `320`；**已选中 = `128` / `144` / `160` / `192`**（已选族 = `0x80` + 基准 0/16/32/64）。
落地前请用目标工程实际布局文件复核：同一工程内两族必须成对出现，否则选中态不生效。

> 源冲突注记（保留供核对，不作为正文）：`bkinfom-grammar.md` 另给 `258` / `130` 并标为「radio-check」。按 §2.1 算术，`258` = `256+2`、`130` = `128+2`，**均含禁用标志 `2`**，是「选中/未选中 + 禁用」的组合态，不是纯选中态。写样式时若只写 `258/130`，控件在非禁用状态下不会高亮。

**分段 radio 的硬约束**：已选态必须用上述 radio 状态位。误写成普通按钮的 `16/32/64` → 选中后**永远像未选**。

### 2.3 未确证项（修改时保持原样，勿「修正」）

`98:1(...)` 的确切语义（仅 login.xml 顶层窗口出现一次）；`21(3)` vs `21(4)` 边框样式的精确差异（grammar §3.2 表解「3=实线、4=渐变线」，同文 §8 又把它列为未确证 —— 源自相冲突，照抄现成段落即可）；`40(1)`、`2(15)` 中区域码 24 的含义（仅段 `5:2(24)` 出现一次）；`32(32804)` 大数值字形标志（资源卡片标题用，照抄）；状态码 `8`（skin.xml `272(8,1,0)` 中的 8 含义）。

## 3. 绘制段语法

每段 `类型:对齐(参数)更多(参数)`；类型决定画什么，参数编号决定细节。

### 3.1 `3:` 图片段

`3:<对齐码>(缩放码)3(l,t,w,h)4(@图片名)`

| 项 | 说明 |
|---|---|
| 对齐码 | `2`、`15`、`18`、`33`、`36`、`41`、`48` 均有出现；`15`=拉伸填充、`33`=居中、`48`=居中原始、`41`=内容槽、`36`=居中裁剪 |
| `3(l,t,w,h)` | 相对元素左上角的绘制区域。**w,h 为 0 表示自动取图片原始尺寸**；`3(0,0,0,32)` 常见于「从上往下画 h=32」 |
| `4(@名)` | 图片引用，经 resource.res 的 type_image 注册名解析。也可绑数据：`4({binding field=缩略图})` |

实例（login.xml 关闭按钮，三态换图）：
`{99:1.9.9;98:16(0)32(1)64(1)2(2);3:2(48)3(24,24,24,24)4(@close1.svg);3:2(48)3(24,24,24,24)4(@close2.svg);3:2(48)3(24,24,24,24)4(@close3.svg);}`
→ 正常画 close1.svg，悬停/按下画 close2.svg，禁用画 close3.svg（24x24 居中）。`3:` 后的第一个括号是对齐方式（48=center）。

`3:41` 内容槽段（绑定子内容）—— `3:41(编号)2(对齐)4()` 是「占位槽」，段内没有实际内容，由运行时填充（如头像图片）：

```text
3:41(1)2(15)4();            ← 空槽（头像底）
3:41(2)2(15)4(@头像框1_120x120_01.png)40(1);  ← 槽2=头像框图片
```

### 3.2 `5:` 矩形/边框段

`5:<对齐码>(区域码)3(l,t,r,b) 20(边宽)21(边样式)26(接角) 22(颜色)23(透明度) 9(圆角×4) [24(渐变) 或 10..16(多层描边)]`

| 参数 | 说明 |
|---|---|
| 区域码 | `3` = 元素整体区域；`15` = 同 3；`7`/`11` = 头部条带（配合 `3(0,0,0,32)` 画顶部 32px 高的标题栏）；`18` = 自定义区域 |
| `3(l,t,r,b)` | 内容区偏移（常与 padding 配合），`3(1,1,1,1)` 即收缩 1px 让边框不糊 |
| `20(1)` | 边框宽度 1px |
| `21(3)` / `21(4)` | 边框样式（3=实线、4=渐变线） |
| `26(1)` | 圆角连接处平滑 |
| `22(颜色)` | 32 位打包颜色，**有符号十进制** |
| `23(透明度)` | 0–255，255=不透明 |
| `9(r,r,r,r)` | 四角圆角半径，可四值不同（如 `9(2,2,0,0)` 仅上圆角） |
| `24(2,角度,起始色,0,结束色,100)` | 线性渐变：2=线性、角度单位为度（0.00=水平、90.00=垂直）、多停靠点格式 `24(2,30.00,C1,0,C2,100,C3,33,C4,66)` 即 0%/33%/66%/100% 四色 |
| `10(1)7(1)11(3)16(1)12(色)13(α)` | 渐变描边（边框自身用渐变色）：`10` 启用、`7` 样式、`12(色)13(α)` 渐变端颜色 |
| `40(1)` | 未知修饰位（头像框、elementUI 常见，照抄即可） |

**最常用的「卡片底」配方**（半透明深色圆角矩形 + 内层渐变描边）：
`5:2(15)20(1)21(3)26(1)22(654311423)23(38)9(2,2,2,2)` → 全区域 1px 描边圆角矩形，填充色 654311423、透明度 38（约 15% 白）。这是 skin.xml 表单容器的实际底色。
**渐变按钮配方**（home.xml 首页卡片）：
`5:2(15)20(1)21(4)26(1)24(2,90.00,-252842773,0,-253105945,100)9(2,2,2,2)` → 垂直 90° 线性渐变，从 -252842773 到 -253105945（深紫到深蓝），圆角 2。

### 3.3 `6:` 内嵌/按下修饰段

语法与 `5:` 完全一致，语义上是「叠加修饰层」——项目中用于内阴影、按压加深、头像底圈等。
实例（头像框选中态）：`6:2(15)20(1)21(3)26(1)22(201326592)23(12)10(1)7(1)11(3)16(1)12(-587202561)13(220)` → 半透明 12/255 的选中蒙层加 220 透明度的渐变描边。

### 3.4 `7:` 文字段

`7:<对齐码>(区域码)3(l,t,w,h)30(对齐标志,文字)21(3)31(@字体名)32(字形标志)22(颜色)23(透明度)`

| 参数 | 说明 |
|---|---|
| 区域码 | `15`=全区域、`3`/`7`/`6`/`11`=局部条带 |
| `3(l,t,w,h)` | 文字绘制区域（w,h 为 0 时自动） |
| `30(对齐标志,文字)` | 对齐标志是 DrawText 式标志之和：`2`=DT_LEFT? `4`=居左、`5`=带图标左对齐、`6`=居中、`7`=整宽居中、`11`/`12`=右上/右下。文字内容直接写在里面，如 `30(2,首页)` |
| `31(@字体名)` | 经 resource.res 的 type_font 注册名，如 `@13b`、`@10b` |
| `32(标志)` | 字形标志：`36`=常规、`37`=加粗、`38`=斜体、`32804`=带阴影/描边变体 |
| `22(颜色)`、`23(α)` | 文字色与透明度 |

实例（main.xml 主导航「首页」，四个交互态各一段文字）：

```text
7:2(15)30(2,首页)21(3)31(@13b)32(37)22(-1291845633)23(178);   ← 正常：灰白
7:2(15)30(2,首页)21(3)31(@13b)32(37)22(-922746881)23(200);   ← 悬停：亮一点
7:2(15)30(2,首页)21(3)31(@15b)32(37)22(-1)23(255);           ← 选中：纯白 + 更大字号 @15b
7:2(15)30(2,首页)21(3)31(@13b)32(37)22(1694498815)23(100);   ← 禁用/按下：半透明
```

段内其他零散编号：`40(1)` 跟随修饰（几乎所有图片段/装饰段都带，保持原样即可）；`10(1)7(N)11(N)16(1)12(色)13(α)` 渐变描边组；`12(...)` `13(...)` 是渐变描边的起/止色对，单独的 `22()23()` 是填充色对。

## 4. 颜色编码与换算

bkInfoM 内所有颜色都是 **32 位有符号十进制整数**（ARGB 打包），而 XML 属性里的颜色是 `#AARRGGBB` 十六进制（如 `textColor="#FDFFFFFF"`）。换算：

```text
有符号数 = ARGB 无符号数超过 0x7FFFFFFF 时的值 - 0x100000000
示例：-1291845633 → 无符号 = 4294967296 - 1291845633 = 3003121663 → 十六进制 0xB2FFFFFF → #B2FFFFFF（70% 透明白）
```

**操作规则：改色时先算无符号值**（`<0` 则加 4294967296），转十六进制得 AARRGGBB，改完再转回有符号十进制写回。工具链用 Python 一行即可：

```python
n = -1291845633; u = n & 0xFFFFFFFF; f"#{u:08X}"        # → '#B2FFFFFF'
c = 0xB2FFFFFF; str(c if c < 0x80000000 else c - 0x100000000)  # → '-1291845633'
```

**humbox 常用色速查**（有符号 → 十六进制，全部经上式验证）：

| 有符号值 | 十六进制 | 用途 |
|---|---|---|
| `-1` | `#FFFFFFFF` | 纯白文字（选中态） |
| `-1291845633` | `#B2FFFFFF` | 70% 白文字（正常态） |
| `-922746881` | `#C9FFFFFF` | 悬停文字白 |
| `-14736351` | `#FF1F2421` | 深墨绿——强调按钮文字色 |
| `654311423` | `#26FFFFFF` | 15% 白——卡片底色 |
| `-3618616` | `#FFC8C8C8` | 浅灰——头像底圈 |
| `-587202561` | `#DCFFFFFF` | 86% 白——登录按钮底 |
| `-1579033` | `#FFE7E7E7` | 白色滚动条 |
| `1503907412` | `#59A3CE54` | 复选框禁用态（绿调） |
| `1694498815` | `#64FFFFFF` | 39% 白——按下文字 |
| `419496450` | `#19010202` | 10% 深色——输入框底 |
| `855638015` | `#32FFFFFF` | 20% 白——悬停底 |
| `687865855` | `#28FFFFFF` | 16% 白——悬停描边底 |
| `352321535` | `#14FFFFFF` | 8% 白——内层描边 |
| `-419430401` | `#E6FFFFFF` | 90% 白——主按钮正常底 |

## 5. 命名样式复用与修改守则

**命名样式复用 `bkInfoM="@名称"`** —— resource.res 的 `<type_bkInfo>` 节注册可复用样式，布局里直接引用名称（等价于 CSS class）：

```xml
<buttonUI bkInfoM="@滚动条" transparent="true" childType="scrollBarV.button" />
```

humbox 已注册的命名样式（18 个）见本节 §6.4。**同类控件多处出现时优先定义命名样式再引用**，避免逐处复制长字符串。

**修改 bkInfoM 的实操守则**

1. **先找同款**：项目内 99% 的样式诉求都有现成配方（按钮、卡片、输入框、单选、滚动条……）。在 `布局文件/` 里全文搜索目标样式关键词（如 `9(4,4,4,4)` 圆角4、`24(2,90.00` 垂直渐变）复制段串改参数，而不是从零拼。
2. **段索引联动**：增删绘制段会改变后续段的索引，`98:` 里的映射必须同步改。改之前先数一遍段。**bkInfoM_nameT 同步**：设计器用 `bkInfoM_nameT="0(矩形)1(文字)"` 记录每段语义；手写时补上（或至少不删除）。
3. **对齐码宁抄勿猜**：`2/3/6/7/11/15/18/33/36/41/48` 各值的确切含义未 100% 确证，**一律从项目现成段落抄对齐码**，只改颜色/尺寸/圆角/文字等确定参数。
4. **图片名必须已注册**：`4(@名)` 里的名字要在 resource.res 的 type_image 有对应条目，否则运行时不显示。
5. **保持 `;` 收尾**：每段末尾 `;`、`}` 前的最后一段也带 `;`，与项目所有实例一致。

**按钮禁用层与圆角配方** —— `bkInfoM` 里：

```text
98:16(0)32(1)64(2)2(3)
     │    │    │   └─ disable → 第 4 个绘制块（索引 3）
     │    │    └─ down
     │    └─ stay/hover
     └─ leave
```

| 现象 | 原因 | 修法 |
|------|------|------|
| 空闲时「停止」等钮 **特别方**，旁边启用钮却是圆角 | 禁用时无对应层，回退系统默认方角 chrome | 给样式加 `2(n)` + 圆角层（含 `40(1)9(8,8,8,8)`） |
| 启用后突然变圆角 | 同上，只在 leave/stay 画了圆角 | 禁用层也要同样的圆角参数 |

**经验**：凡代码里会 `.启用(假)` 的按钮（停止扫码、停止刷新、主 CTA、次要等），样式从第一天就按 **四态** 写，不要只写三态。主操作 / 次要 / 危险应共用同一套圆角 `9(8,8,8,8)`，禁用层不要省略。

| 命名样式 | 禁用层建议 |
|----------|------------|

## 6. resource.res 注册与资源引用

> 来源：`architecture.md` §2、`file-map.md` §4、`00-xc-xml-schema.md` §21/§23、`09-tool-window-tokens.md` §3、`07-pitfalls-and-checklist.md` §4、`xcgui-humbox/skill.md`

**三层引用模型**：布局 XML 里写 `@名称` → resource.res 注册表解析 → 实际文件在 `资源文件/`。图片/字体/符号ID/复用样式**未注册即静默失效**。
`资源文件/resource.res` 是 XML（不是二进制），根元素 `<resources>`，六个子节。**所有图片、字体、符号 ID、可复用样式都必须先在这里注册**，布局文件再以 `@名称` 引用。
> 源注记：`architecture.md` §2 正文说「六个子节」，但按其 2.1–2.5 列出的 `type_` 节名共 7 个（`type_image` `type_id` `type_font` `type_bkInfo` `type_string` `type_color` `type_nameTable`）。**以实际工程 `<resources>` 子节为准。**

### 6.1 `type_image` — 图片注册

```xml
<image name="login_sd.png" value="login_sd.png" loadType="file" style="image9" rect9="30,28,30,32" />
<image name="close1.svg"   value="close1.svg"   loadType="file" style="default" svgAlpha="255" svgRotateCenter="1" />
<image name="mine_vip_bg.png" value="mine_vip_bg.png" loadType="file" style="fixedRatio" />
```

| 属性 | 说明 |
|---|---|
| `name` | 引用名（布局里 `@name`） |
| `value` | 资源文件/ 下实际文件名 |
| `loadType` | 项目恒 `file` |
| `style` | `default`=原样 / `image9`=九宫格拉伸 / `stretch`=整体拉伸 / `fixedRatio`=锁定宽高比 |
| `rect9` | 九宫格四边距 `l,t,r,b`（仅 image9） |
| `svgAlpha` | SVG 透明度（仅 SVG） |
| `svgRotateCenter` | SVG 旋转中心标记（项目恒 `1`） |
| `center` | 是否中心锚定（fixedRatio 时出现，`"false"`） |

**新增图片流程**：① 文件放进 `资源文件/` ② 在 type_image 加一行注册（照同类图抄属性）③ 布局里 `4(@名)` 或 `image="@名"` 引用。**删除图片时反向执行**，并全文搜索确认无引用。
SVG 注册写法（属性名以 hum `资源文件/resource.res` 为准）：

```xml
<type_image>
  <image name="mini.svg" value="svg\mini.svg"
         loadType="file" style="default"
         svgAlpha="255" svgRotateCenter="1" />
  ...
</type_image>
```

**`type_image` 体量（humbox）**：约 **230 条**，与 `资源文件/` 目录一一对应（不一致处见 `skin-platforms.md` 已知问题）。常用族：`close{1,2,3}.svg`、`navbtn_icon_{skin,update,login,install}_{01,02,03}.svg`、`combobox_icon_{01,02,03}.svg`、`help_icon_*.svg`、`vip_icon_{01..05}.svg`、`first/second/third_icon_{01..06}.svg`、`Vv_s_v{1..10}.png/v{01..09}.svg`、`头像框{1,2,3}_{32,80,120,160}x{32,80,120,160}_{00..05}.{png,svg}`、`login_sd.png`/`xy_sd.png`/`updater_wnd_sd.png`（9-patch 窗口边框）。

### 6.3 `type_font` — 字体注册

```xml
<font name="13b"  size="13" fontFile="font\Semibold.ttf" />
<font name="13_yh" size="13" fontName="微软雅黑" />
<font name="13_vv" size="13" fontFile="font\HUMUINUM2.ttf" />
```

### 6.6 资源引用语法与部署硬约束

以 `@` 开头走资源：`@yahei_9`、`@refresh.svg`、`@按钮_次要`、`@文本_标题`。颜色可用 `#RRGGBB` / `#AARRGGBB`。**不要写磁盘绝对路径。** SVG / 图片必须进 `resource.res` 的 `<type_image>`，并随 exe 带上资源目录。

| 使用场景 | 写法 |
|------|------|
| 按钮左图标 + 文字 | `imageIcon="@refresh.svg"` |
| 窗控 / 纯图标钮 | `bkInfoM` 图片层 `3:2(15)4(@mini.svg)`，可按状态换图 |
| 品牌角标 / 小节标题旁图标 | 小 `layoutEleUI` + `3:2(15)4(@logo.svg)` |
| 组合框右侧箭头 | `combobox_x.svg`～`combobox_x4.svg` |

**命名空间限定名 `@<命名空间>:\<条目>`**：`.res` 侧除了裸名 `@按钮_次要`，还大量出现带命名空间的引用（示例工程 `WmUi`，源 `炫彩界面库.mdc` §9.1–§9.6）：

- 资源条目命名空间：`@WmUi:\xxx`、`@WmUi_Base:\xxx`——`WmUi_Base` 放字体与通用色，`WmUi` 放主题资源（浅色/暗色各一套）。
- `bkInfoM` 里写 `bkInfoM:@WmUi:\某样式;`（等价于 `"@WmUi:\某样式"`）；文字色/光标色写 `@WmUi_Base:\黑色/白色` 一类主题色资源，或 `textColor="@WmUi:\\主文本色"`（源文件里该路径是双反斜杠写法）。
- 滚动条滑块这类「XML 里没有直接声明对象」的部件，靠 CSS 选择器映射到 `@WmUi:\滚动按钮_水平/垂直`。
- **加载顺序（硬要求）**：先 `WmUi_Base.res`（字体/通用色）→ 再主题 `WmUi.res` → 再主题 `WmUi.css`。示例工程按 `WmUi\WmUi_Base.res` + `WmUi\Light\*` / `WmUi\Dark\*` 两段式组织（源文件里 `WmUi\\Light\\WmUi.res`、`WmUi\\Dark\\WmUi.css` 这类双反斜杠写法也出现，照抄目标工程即可）。顺序颠倒会出现字体/颜色引用缺失；加载时机在 `显示(真)` 之前，主题切换后要 `重绘()`。
- 只想要少量控件套这套皮肤时，可按用到的最小集裁剪 `.res` 的 `<item>` 条目与 `.css` 的选择器，不必整套拷贝。

**部署**：运行目录（如 `Release64\`）必须有：布局 XML、`resource.res`、`svg\*.svg`、列表 / 组合框项模板。**只改 XML 不拷 svg / res → 图标空白或样式丢失。** 黑底按钮用浅色 SVG（如 `*_w.svg`）；浅底按钮用深色/品牌色 SVG。工程布局在 `布局文件\` 子目录时：运行目录也要有 `布局文件\`（含 `List1.xml`、`combobox_item.xml`）。

**样式复用优先级**

| 场景 | 优先 |
|------|------|
| hum / 工具窗 | `resource.res` 命名样式：`@面板_窗壳` `@按钮_主操作` `@按钮_次要` `@按钮_危险` `@按钮_分段` `@复选框` `@编辑框_圆角` |
| humbox | 深色玻璃 + 亮黄绿强调；顶栏 Tab |
| 示例工程 CSS | `布局_描边卡片` `重要按钮` `标签导航按钮` 等 |
