## 1. 布局、资源与 bkInfoM

**改布局前**：① 定位文件（`skin-platforms.md` §2.7 依赖图）② 读目标文件与上下游（容器/模板）③ 涉及 bkInfoM → 先读 `bkinfom-res.md` §1–§5；涉及 `layout.*` → 读 `interface-xml.md` §2 ④ 改动最小：抄现有配方改参数，不发明新模式 ⑤ 完成后全文搜被改的 `@资源名`/`@ID`/`name`，确认无遗漏引用。

- **三层引用**：布局 XML 写 `@名称` → `resource.res` 注册表 → `资源文件/` 实际文件。**未注册即静默失效**（不报错，只是不显示）。

- **XML 不是单根**：`<head />` 与 `<windowUI>`/`<layoutPanel>` 并列；注释决定文件类型。标准 XML 单根校验会误判 —— **以炫彩 IDE 为准**。

- **布局盒子才排布**：只有 `windowUI`（`enableLayout="true"`）、`layoutEleUI`、`layoutFrameUI` 是布局盒子；`layoutPanel` 不是，里面要再放 `layoutEleUI`。

- **默认水平**：`layout.horizon` 默认 `true`（横排）。竖排必须显式写 `layout.horizon="false"`。

- **bkInfoM 是分段序列**：`{99:版本;98:状态映射;段0;段1;…}`。**增删段会移动索引，`98:` 必须同步改。**

- **`@名` 必须已注册**：写 `@xxx` 前确认 `resource.res` 有对应条目（`type_image` / `type_font` / `type_id` / `type_bkInfo`）。

- **`98:` 状态索引联动**：bkInfoM 增删绘制段后必须同步改 `98:` 映射里的索引；`bkInfoM_nameT` 同步。

- **`name` 不可随手改**：宿主代码按 `name` 找元素（`main_body`、`_up_*` 槽、`皮肤_..._编辑框` 等语义名）。

- **状态码 `2` = 禁用（disable）**，不是选中态；radio/check 已选态用 `128/144/160/192`，未选中用 `272/288/320`（依据与源冲突见 `bkinfom-res.md` §2.1/§2.2）。

- **会 `.启用(假)` 的按钮必须在 `98` 里写 `2(n)` 禁用层**，否则空闲时回退系统方角 chrome。

- **属性禁止写在自闭合 `/` 后面**（如 `<x a="1" / b="2">`）—— IDE 直接解析失败。

- **列宽一致**：`添加列文本(宽,…)` 必须与项模板里每列 `layout.width` 一致，否则表头错位。

- **项模板三条死命令**：根 `enableCanvas="false"`、`mouseThrough="true"`、`drawBorder="false"`。

- **`Test.xml` 不是规范**：设计器草稿，正式风格以其他布局文件为准。

- [ ] SVG：`resource.res` 已登记全部用到的 svg；运行目录 `svg\` 文件齐全；黑底用浅色图标、浅底用深色/粉色图标

- [ ] XML：IDE 能打开主布局（无 ` / attr` 类语法错误）；所有 `name` 与 `.xc` 绑定一致；`itemTemplate` 文件存在且已部署

- [ ] 布局：竖排容器已写 `layout.horizon="false"` + `layout.spaceRow`；吃满高度用了 `:n` / 外层包列表；列宽一致；项模板三条死命令齐备

- **窗壳决定透明模式**：`shaped` 必须有窗口级不透明底（工具窗 `@面板_窗壳`、hum 产品 `@wnd_bg.png`）；humbox 主窗是 `shadow`。子控件 `bkColor` 救不了。

## 3. 炫语言、模块调用与封装

- **模块封装是「注解驱动」**：`module_*.h` 的 `//@` 注解供 IDE 解析；C++ 侧标识符必须英文，中文只出现在 `//@别名`。

- **UTF-8**：布局/资源文件 UTF-8 无 BOM；模块 `.h`/`.cpp` 必须 **UTF-8-BOM**。混用编码会导致中文乱码。

- **`common.xh` 不能 `#include` 模块头**：模块由 `*.xcproj` 的 `<modules>` 注入。

- **调用索引不是编译证明**：现成模块的实际别名、签名、隐藏区、架构条件和初始化/释放顺序以当前头文件及 `.xc` 示例为准；`show` 的未解析依赖或同名入口冲突先定位清楚，不能自动挑第一个。源码哈希变化时先重建索引（`xc-modules.md`）。

- **路径含中文或 `[` `]` 必须用 `-LiteralPath`**：如 `核心[官方]`、`系统API(前缀分类法)`、`炫易模块(MD5)`。PowerShell 会把 `[` `]` 当通配符，静默匹配失败。

- **`CXBytes` 没有 `.data()`**：读用 `get()`（返回 `const BYTE*`），写用 `resize()`/`alloc()` 的返回值。

- **炫语言不支持重载**：用 `func()` / `func2()` / `func3()`，禁止同名重载暴露给 IDE。

- **`@示例` 不支持缩进**，用 `--` 代替缩进。

- **`//@别名` 可变参括号内不要写 `...`**；无参保留空括号 `()`；参数列表逐个写出参数名。

- **类型名与函数名同命名空间，改名必须先查重**：结构体与同名函数不能并存；改名要按「该名字的全部声明文件」同批处理，结构体改名还要同步 `host_forward.h` 之类前向声明头（UTF-8-BOM）；批量替换工具切字符串时必须清空代码缓冲，否则代码段会被写两遍，详见 `xuanlang-lang.md` §2.4.1。

- **不使用 `sessions/`、`.codegraph/`**：源 `xc-代码/skill.md` 第 35 行原文：「`sessions/` 与 `.codegraph/` 不是技能材料。」

- **不臆造**：类名、属性、API、注解、色值必须可溯源；不确定的写「源材料未确证」，不猜。

- [ ] 模块：`.h`/`.cpp` 为 UTF-8-BOM；无同名重载暴露；字符串返回 CX 类型；模板已 `//@隐藏`；`CXBytes` 不用 `.data()`

## 4. 构建、迁移与部署

本仓库使用 `cli-anything-xcide build --diagnostics` 在新建的私有 IDE 中构建；下述旧 MCP 流程仅适用于明确选择那个外部工作流时。无需安装 MCP，后台编译和测试以本技能入口和 CLI 手册为准。

- **构建证据不可偷换**：静态扫描、`xc_build` 的 F7 已投递、旧 EXE／旧报告都不是“最新源码编译成功”；须核对当前工程、实际错误列表、新 EXE 与 AMD64 架构，详见 `module-packaging.md` §13。

- **续做按本轮取证**：每轮唯一 RunId／独立 before，原指纹基线与旧 before 冻结；绑定真实命令退出码、源码／资源／EXE 与报告哈希，文档修改后重算指纹；历史差异不得用 -Create 消除，详见 `module-packaging.md` §13.4。

- **磁盘 `.xc` 改动不等于 IDE 已重新解析**：逐个打开改动文件并同步编辑缓冲后再构建；打开 `.xcproj` 标签也不等于激活构建工程，必须另查当前工程。构建配置在 IDE 缓存与磁盘不一致时分别核实，详见 `module-packaging.md` §13.3。

- **版本经验要标注范围**：端口、工具数、IDE 首次 F7 行为和表达式兼容以当前安装实测为准；修改前先查实际 schema／头文件／构建器源码，不写成跨版本定律。

- [ ] 构建：构建结果的工程路径与目标一致；实际编译错误 0；新产物架构正确；源码快照与构建时一致；没有用旧产物或静态检查代替真实构建

- [ ] 验证：测试数据根与本轮 RunId／before 独立；真实／预期退出码及新报告指纹齐全；`not_run` 与历史证据单列；原文件路径／长度／哈希及历史差异前后一致，未覆盖冻结基线或未知输出

- [ ] 部署：先区分磁盘／内嵌 UI；磁盘部署同步 XML/res/svg/模板/WmUi/字体和匹配 DLL，内嵌部署重建并核对 PE 资源；仅携带实测必需运行文件，链接中间件完整留存；改 `.xc` 或内嵌 XML 必须重建（§13.4）

## 5. UI 验证与实机联调

- **UI 三层证据不可混用**：后台数据／适配器计数、实际可见单元格、真实鼠标动作结果分别观察；模态文件对话框关闭后才能检查回填和业务结果，立即读取可能拿到旧状态，详见 `xcgui-code.md` §6.7。

- **三类句柄不可想当然混用**：`HWINDOW`、系统 `HWND`、`HELE` 分别走对应 API；窗口可见性通过本进程系统 HWND 检查。C/C1 回调是否包含来源元素句柄以当前头文件为准，详见 `xcgui-code.md` §6.5。

- **check 的业务状态优先于默认翻转**：对由业务结果决定选中的按钮，定向设 `是否拦截=真` 并同步实际状态，失败不能呈现假成功。普通配置复选框不要一并拦截。

- **WmUi 控件尺寸不等于绘制范围**：24px checkbox 仍须检查实际 bkInfoM/CSS 宏和像素 bbox；若宏按 20px 设计，先修绘制区并让 CSS 实际指向新宏，详见 `ui-verification.md` §2。

- **同组 radio 状态按顺序写入**：先对组内全部成员 `SetCheck(false)`，最后只对目标 `SetCheck(true)`；不要用目标真与其他成员假混排循环，详见 `ui-verification.md` §3。

- **截图和启动结果必须证明已绘制**：`PrintWindow`/`WaitForInputIdle`/工具成功返回不能代替非黑帧、标题和唯一选态核验；真实游戏及其他 DPI 未测时必须保留范围声明，详见 `ui-verification.md` §4、§6。

- **实机联调要在一次命令内跑完**：工具调用结束会回收同作业的子进程，GUI 句柄随之失效；点击基准按当次截图换算、输入前校验前台与 `WindowFromPoint` 归属、`PostMessage` 驱动不了 XCGUI、OCR 需放大并归一化，详见 `ui-verification.md` §8。

- [ ] 交互：真实 radio／按钮事件已测；失败后的 check 与实际状态一致；辅助窗关闭／重开、主窗正常退出和线程／hook 清理有实际断言

- [ ] 渲染：当前 EXE 被动冷启动得到非黑帧，初始标题和唯一选态正确；每个页签实际点击后核对标题与唯一选态，不用文件名或工具返回值代替

- [ ] 像素：WmUi checkbox 的 CSS 实际指向正确宏，像素 bbox/留白在声明的 DPI 下通过；控件尺寸本身不算证据

- [ ] 输入范围：后台消息只发给隔离私有 sink，发布配置未被覆盖；真实游戏、其他 DPI 和未执行外部目标单列为未测

- [ ] 切页：同组代码同步先全部 `置选中(假)`，最后只对目标 `置选中(真)`；确认实际唯一高亮；隐藏面板注意首次布局 0×0（先全部可见 → 显示 → 再切页）
